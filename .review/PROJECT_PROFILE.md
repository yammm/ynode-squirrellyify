# Project Profile

## Identity

- Project name: @ynode/squirrellyify
- Purpose: Fastify Squirrelly rendering plus deterministic CSP-friendly browser client-module compilation.
- Intended users: Node.js application developers and maintainers of the @ynode ecosystem.
- Maturity: stable
- Visibility: public npm package and public GitHub repository.

## Supported environments

- Runtime contract: Node.js `>=20.19.0`; ESM package with public TypeScript declarations.
- Exact CI boundaries: Node.js 20.19.0, 22.13.0, and 24.0.0.
- Runtime policy: Node.js 20 is retained until the next package major despite upstream end of life; Node.js 22 and 24 are recommended. New majors require CI evidence.
- Package manager: npm 11.17.0 with the committed `package-lock.json`.
- Peer and service compatibility: Fastify 5.x and Squirrelly ^9.1.0.
- Platforms: Full gates run on Ubuntu; packaged CLI smoke tests and filename-safe hook logic run on Ubuntu and Windows.
- CI trust model: GitHub-hosted runners, least-privilege job tokens, immutable third-party action SHAs, no publish token, and npm trusted publishing from the tag-only release workflow.

## Public contracts

- The default and named exports, TypeScript declarations, Fastify decorators, scoped render configuration, client-module artifacts, CLI grammar and statuses, and generated declaration/source-map shapes.
- `package.json#exports`, packed files, README examples, generated JSDoc, and `CHANGELOG.md` are release contracts.
- Only documented entry points are supported; internal `src` paths not exposed by `exports` are private.

## Architecture and ownership

- Trust and external boundaries: Template names and files, Fastify request/reply state, Squirrelly helpers and filters, generated browser JavaScript, config modules, filesystem output, and CLI streams.
- Runtime code owns behavior; `index.d.ts` owns the matching public type surface.
- Repository scripts own deterministic docs, packed-consumer checks, staged-file checks, and release preparation.
- Generated documentation lives in ignored `docs/` and must be regenerated from source.

## Consequential project invariants

### Invariant 1: Template resolution cannot escape configured roots

- Requirement: Template resolution cannot escape configured roots.
- Risk if violated: Traversal or ambiguous template names can disclose or execute unintended files.
- Safe path: Normalize and validate names before resolution, preserve Fastify encapsulation, and reject paths outside the owned view roots.
- Authoritative evidence: public documentation, declarations, source, and focused tests in this repository.

### Invariant 2: Client builds are deterministic and CSP-friendly

- Requirement: Client builds are deterministic and CSP-friendly.
- Risk if violated: Runtime compilation, eval-like output, partial replacement, or nondeterministic declarations can break CSP and corrupt deployed assets.
- Safe path: Compile all modules before replacement, reject unsupported constructs, emit stable artifacts, and leave unchanged files untouched.
- Authoritative evidence: public documentation, declarations, source, and focused tests in this repository.

## Security and privacy

- Vulnerability reporting and supported versions are defined in root `SECURITY.md`.
- Secrets, credentials, private paths, and reusable tokens must not enter source, fixtures, logs, workflow output, packed artifacts, or generated documentation.
- Dependency updates are reviewed weekly. Production advisories fail at moderate severity and the complete development tree fails at high severity.
- Accepted security exceptions require an owner, reachability rationale, remediation target, and expiry; none are currently recorded.

## Release and versioning

- SemVer governs public behavior and types.
- Development commits may carry autover build metadata; such versions are never publishable.
- Run `npm run release:patch`, `npm run release:minor`, or `npm run release:major` on clean synchronized `main`.
- The helper validates the bumped package, creates a signed and signed-off commit plus signed tag, and never pushes.
- Push with `git push --follow-tags`; `.github/workflows/release.yml` verifies the signed tag and publishes the exact tested tarball through npm OIDC with provenance.
- The npm trusted publisher must be restricted to this repository and `.github/workflows/release.yml`.

## Known constraints and accepted debt

- Node.js 20 is upstream-EOL but remains in the current major compatibility contract. Remove it at the next major release and update `engines`, CI, README, and `SECURITY.md` together.
- Local service integration is conditional where no disposable service is configured; skipped tests are not evidence of live integration behavior.
- No additional accepted debt is recorded.
